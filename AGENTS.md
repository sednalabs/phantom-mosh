# Engineering Phantom Mosh

Freeze a full remote commit before source-grounded review. Record the engagement,
review generation, publication parent, output commit and exact CI checkout
separately. Reconcile remote movement before publishing; use non-force updates
and verify the immutable output tree. Open reviewable PRs. Do not merge, release,
change repository protection or replace deployed binaries without authorization.

Keep upstream Mosh behavior and licensing intact unless a change explicitly
owns that integration. The draft record layer is experimental. A green unit test
is not cryptographic review, terminal acceptance or fingerprint-resistance proof.

For record changes, update the protocol specification, independent oracle and
adversarial tests together. Test rejected-packet state preservation, nonce
ownership, key retirement, counter exhaustion, replay, out-of-order delivery,
acknowledgement-gated updates and loss/outage recovery. Never replace rejection
with silent fallback to v2 or retain an all-epochs root to make recovery easy.

MoshWatch supplies evaluator truth only. Do not feed host session IDs, process
metadata, real RTT, key epochs or migration labels to passive classifiers. Keep
observation failures and null results visible. Do not publish private research
artifacts or imply that PHANTOM WEAVE generations are certification levels.

Use the inherited .clang-format (version 14). Tests must not disappear under
NDEBUG. The new core can be tested with CMake at src/phantom; keep inherited
Autotools CI enabled. Track exact test generations and unresolved review limits.
